# Phase 4F: Better Auth Foundation

## Status

Implementation complete pending automated PR validation.

## Delivered

- Added Better Auth 1.6.23 and its Prisma adapter through a one-time GitHub Actions dependency workflow.
- Added the Better Auth User fields and core Session, Account and Verification models.
- Reused HomeVault User as the immutable application identity mapped to household memberships.
- Added a server-only Better Auth configuration for verified email/password.
- Disabled account linking and social providers.
- Added a fail-closed authentication API route.
- Added a provider-neutral email boundary that refuses delivery until configured.
- Kept public builds and sample routes operational without database or auth secrets.
- Added unit and deployment-smoke contracts for configuration and unavailable auth behavior.

## Runtime Boundary

The auth handler loads dynamically only when all required runtime values exist:

- `DATABASE_URL`;
- `BETTER_AUTH_SECRET`;
- `BETTER_AUTH_URL`.

Signup additionally requires:

- `AUTH_SIGNUP_ENABLED=true`;
- a non-disabled `AUTH_EMAIL_PROVIDER`;
- `AUTH_EMAIL_FROM`.

Without these values, the auth endpoint returns a private, no-store 503 response and creates no account or session.

## Database Boundary

The Prisma schema contains the supported Better Auth core models but no production migration is applied in this phase. Production migration baselining and deployment occur in the dedicated production database operations phase.

The canonical synthetic seed user is marked verified but has no credential Account. No review password or secret is committed.

## Not Yet Enabled

- Live email delivery.
- First-home onboarding.
- Session-based current-home resolution.
- Household authorisation enforcement.
- Account deletion.
- Social login.
- Production database migrations.
