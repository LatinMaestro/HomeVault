# Production Storage Architecture

## Status

Provider direction locked. Provisioning and uploads follow production identity and household authorisation.

## Decision

HomeVault will use **Vercel Private Blob** for production household attachments.

Vercel Private Blob reached general availability on 30 June 2026. Private blobs require authenticated operations, support signed delivery and can use short-lived Vercel OIDC credentials. Neon Object Storage remains Beta and is not on the production critical path.

Official references:

- [Vercel Private Blob GA](https://vercel.com/changelog/vercel-private-blob-is-now-generally-available)
- [Private storage](https://vercel.com/docs/vercel-blob/private-storage)
- [Blob security](https://vercel.com/docs/vercel-blob/security)

## Security Model

- Blob access is private.
- Every upload, download and delete operation validates the signed-in HomeVault user and active household membership on the server.
- Database metadata stores an opaque blob pathname/key, never a public bearer URL.
- Download responses use short-lived signed access or an authorised server route.
- Pathnames are household-scoped and generated by the server.
- Original filenames are display metadata only and are sanitised.
- Blob credentials never reach client JavaScript.
- OIDC is preferred over long-lived Blob tokens where the deployment supports it.

## Initial File Policy

The first release accepts common household-document formats only:

- PDF;
- JPEG;
- PNG;
- HEIC/HEIF only after verified platform support.

Initial limits:

- maximum 15 MB per file;
- one attachment per Document metadata record;
- no executable, archive, office-macro or unknown binary formats;
- no OCR, AI extraction or email ingestion;
- downloads default to attachment-safe behavior unless an approved inline type is explicitly handled.

## Upload Flow

1. Validate session and household membership.
2. Validate the target metadata record belongs to that home.
3. Validate declared size, extension and detected content type.
4. Generate a household-scoped random pathname.
5. Upload to the private store.
6. Persist blob metadata only after upload succeeds.
7. Compensate by deleting the blob if metadata persistence fails.
8. Never mark an attachment available before both sides are consistent.

## Deletion And Retention

- Replacing a file removes the previous blob only after the new metadata commit succeeds.
- Deleting an account or home queues or performs attachment deletion before final lifecycle completion.
- Failed cleanup is recorded for retry without exposing the file.
- No generated exports are retained.
- Backup and legal-retention behavior must match the public policy.
- Permanent record deletion remains unavailable until account lifecycle is implemented.

## Malware Boundary

Vercel Blob provides private access controls and platform security headers; it is not treated as application-level malware validation. HomeVault will use strict type/size allowlists and attachment-safe delivery first. A dedicated malware scanning service requires separate provider and cost approval before broader file types are accepted.

## Provisioning Gate

A client or authorised project owner must create/connect a private Blob store to the HomeVault Vercel project when implementation reaches live storage testing. No store or credential is required for build, sample fallback or pre-provisioning code review.
